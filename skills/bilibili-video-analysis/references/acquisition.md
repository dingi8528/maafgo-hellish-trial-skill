# 获取、速度与完整性

## 本技能附带的脚本

`scripts/bilibili.py` 使用 Python 标准库请求公开视频详情、播放流、空间列表与可选评论；没有 Cookie 参数或自动登录流程。以下接口只是实现线索，运行时可能变化，以实际响应为准。

| 目的 | 接口/命令 |
|---|---|
| 简介、作者、分P与 CID | `/x/web-interface/view`；`inspect` 或 `video` |
| 公开视频播放流 | `/x/player/playurl`；指定实际 CID |
| 投稿快照 | `/x/space/arc/search`；`space --order pubdate --limit N` |
| 小流量实测 | `inspect`；每源最多 1 MiB，不保存媒体 |
| 离线完整性复验 | `verify`；不请求网络 |
| 关键帧 | `frames --times 秒数列表` 或 `--interval 秒` |

公开接口不保证持续可用，空间列表风控不能解释为“没有攻略”。先用普通网页或正常搜索定位 BV；选择搜索结果时检查真实作者 UID 与当期信息，不能只看昵称。

## 速度协作

1. `inspect` 输出 `download_estimate.json`，分音画源列实际采样字节、elapsed、rate 与总大小。HTTP Range 被忽略也只读取上限字节；采样会实际请求数据，不是仅测 HEAD。每次仅测选中P；下载多P之前逐P使用 `inspect --page N --out 各自目录`，部分大小未知时仅汇总已知部分，不推算整部总 ETA。
2. 若 Content-Range 可知完整大小，使用其总量；不能把 206 响应的一小段 Content-Length 当作整个文件大小。没有可信大小时 ETA 是 `null`，解释为未知。
3. 估计不包含完整解码时间；分段/分离流的总等待时间应累加各源估计，并说明存在波动。短样本速率不能当作服务长期带宽承诺。采样用 `read1` 短分块读取，每轮检查剩余墙钟时间，读超时按 2 秒与剩余时间取较小值；已采到字节时保留测量结果并注明 `sample_stop_reason`。读超时、采样时间或字节上限均不等于源 EOF，也不证明完整媒体。
4. `video` 把每个成功读到的短分块立即写入 `.partial`，输出实际速率，不要求凑满 64 KiB 才反馈。小于 128 KiB/s 且剩余超过 300 秒或未知时停止，由用户选择如何处理；`--allow-slow` 仅在用户愿意等待后使用。单次读无数据超时仍为 5 秒，超时不在同一失效缓冲上反复读；完整重试会重新下载并校验，不声称断点续传。
5. 第一次采样就很慢或报错时不要并发大量源“碰运气”，也不私自切换代理/付费服务。保留已完成的元数据工作，继续独立的任务梳理。

## 联合校验

下载记录中保留期望和实际字节数、服务器 Content-Length、源时长、容器时长、每轨解码覆盖、音轨有无、哈希及错误。未知项保留未知。

- `durl` 多段必须按顺序拼接，DASH 音画独立源需要合并。缺音轨必须记录。
- 各音画轨单独完整解码，以原始 PTS 与帧/采样时长核对覆盖；可变帧率不能按名义 FPS 粗算。
- 容器长度可能由音轨撑满，而视频已被截断；反之亦然。`ffmpeg` 退出 0 并不足以放行。
- 已存在正式文件先复验，失败保留，不覆盖；缓存下载也不能跳过校验。
- 未提供源时长/大小时，离线 `verify` 只能证明本地解码自洽。用户本地文件可用，但说明源完整性未独立证实。

目录由 `--out` 决定：`01_视频` 保存媒体，`02_抽帧` 保存原帧和联系表，`03_数据/{BV}` 保存接口响应、逐P清单与日志。CDN URL 可能过期，不作为长期分享链接。不要公开整个原始响应目录或媒体，只发布必要的攻略链接与自己整理的策略。

## 故障边界

普通网络/5xx 故障最多额外重试一次。单独 CDN 401/403/410 可以重新获取一次公开 playurl 以区分链接过期，但仍被拒绝则停止；不重复刷新受限接口。平台风控、登录与权益限制保留原因；可以接受用户的本地文件或另一个正常可访问攻略。

FFmpeg 选择顺序是显式 `--ffmpeg` → PATH → `imageio_ffmpeg`；现有安装优先。脚本不会替用户安装依赖。`python -m unittest discover -s scripts -p test_bilibili.py` 可运行本地回归，不访问B站；生成的短测试媒体位于临时目录。
